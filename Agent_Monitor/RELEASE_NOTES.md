# Release Notes - Agent_Monitor

## [펌웨어 0.6.2] - 2026-11-11
### 🩹 BLE 연결 간격 요청 제거 — Windows 노트북에서 연결 실패 · BT 마우스 멈춤 (PC 클라이언트는 0.6.2 그대로)
- **버그 수정**: 펌웨어 0.6.1 이 연결 직후 요청한 연결 간격 15~30ms 를 Windows 가 레지스트리(`HKLM\SYSTEM\CurrentControlSet\Services\BTHPORT\Parameters\Devices\<주소>\LERemoteConnParams*`)에 저장해 다음 연결부터 처음부터 적용했다. 노트북 내장 Bluetooth 에서는 이 값으로 새 연결의 서비스 탐색이 끝나지 않아(연결 시간 초과) 트레이가 회색으로 남았고, 연결을 시도하는 동안 BT 마우스가 멈췄다. 장치를 0.6.0 으로 되돌려도·Bluetooth 를 껐다 켜도 저장된 값 때문에 계속 실패했다.
- 연결 간격 요청(`updateConnParams`)을 빼고 **데이터 길이 확장(251)만** 요청한다 (Windows 는 이 값을 저장하지 않는다).
- **0.6.1 을 쓴 Windows PC 복구**: 관리자 PowerShell 에서 저장된 값을 지우고 재부팅한다 —
  `Remove-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Services\BTHPORT\Parameters\Devices\<장치 주소 소문자 12자리>' -Name LERemoteConnParamsIntervalMin,LERemoteConnParamsIntervalMax,LERemoteConnParamsLatency,LERemoteConnParamsLSTO`
- 실기(Windows 11 노트북 내장 BT): 연결 반복해도 레지스트리에 연결 파라미터가 저장되지 않음, 트레이 BLE 연결·BT 마우스 정상. 2KB 상세 줄 전송(같은 부팅) 0.6.0 4.9초 → 0.6.2 **2.7초**. 크기 905,519 B (69%). 웹 플래셔 배포본 0.6.2 갱신.

## [v0.6.2] - 2026-11-11
### 🔑 BLE 모드에서도 키 자동 등록 · Windows BLE 속도 (펌웨어 0.6.1)
- **버그 수정 — 새 PC 에서 상세 화면 답변이 안 뜨던 문제**: 데몬 기본이 BLE 전용(0.6.0~)이라 USB 가 꽂혀 있어도 키를 등록할 기회가 없었고, 키가 다른 장치의 BLE 버튼 신호(상세 화면 열기·승인·PC 명령)는 모두 거부됐다. 이제 BLE 로 받은 hello 의 키가 다르면 데몬이 **USB 포트를 잠깐 열어 키만 등록하고 바로 닫는다** (`transport.register_key_via_usb`). USB 가 없거나 포트가 사용 중이면 30초마다 다시 시도해 나중에 케이블을 꽂아도 등록된다. 장치가 새 kid 로 hello 를 보내면 성공.
- **펌웨어 — BLE 연결 파라미터 요청**: 연결 직후 연결 간격 15~30ms · 데이터 길이 확장(251) 을 요청한다. Windows 에서 2KB 상세 줄 전송 2.46초 → **0.97초**.
- **버그 수정 — Windows 콘솔 로그**: cp949 콘솔에 없는 글자(`—` 등)가 로그에 있으면 `log()` 가 예외를 내 장치 줄 처리가 멈췄다. 출력할 수 없는 글자는 바꿔 찍는다.
- 크기: 905,635 B (69%). 테스트: 데몬 53건 (BLE 키 불일치 → USB 등록·재시도 간격, `register_key_via_usb` 성공·다른 펌웨어·포트 사용 중). 실기(Windows 11): 임시 키 → 원래 키 자동 재등록, BLE 전송 시간 측정. 웹 플래셔 배포본 펌웨어 0.6.1 갱신 (Windows 에서 빌드).

## [v0.6.0] - 2026-11-10
### ✨ 한글 표시(갈무리7) · 상세 화면 마지막 답변 4페이지 · 데몬 기본 연결 BLE
- **한글 표시**: 화면 글꼴을 [갈무리7](https://github.com/quiple/galmuri)(8px 비트맵, OFL-1.1) 하나로 통일해 영문·한글(11,172자)을 표시한다 (`u8g2_font_galmuri7_kr.h`, 플래시 약 166KB — 변환: U8g2 `bdfconv`). 글꼴에 없는 글자(한자·이모지)는 그려지지 않는다. 줄바꿈은 글자 수가 아니라 **픽셀 폭**(128px, UTF-8 글자 단위)으로 한다. 제목은 글자마다 1px 어긋나게 두 번 그리고 간격을 2px 넓혀 굵게 보이게 한다 (갈무리7에는 굵은 글꼴이 없다).
- **데몬**: 한글을 `?` 로 바꾸지 않고 UTF-8 그대로 보낸다 (`ensure_ascii=False` — 펌웨어 파서가 `\uXXXX` 를 거부한다). 길이 제한은 **바이트 기준**으로 글자 중간에서 자르지 않는다.
- **길이 확대**: 개요 요약 63→96바이트, 승인 요약 120→240바이트, 상세 마지막 답변 120→**1,728바이트**(한글 약 576자). 수신 줄 한계 512→2,560바이트, 시리얼·BLE 수신 버퍼 4KB.
- **마지막 답변 페이지 넘김**: 상세 화면 BTN3 = 이전 페이지 · BTN4 = 다음 페이지 (한 페이지 = 화면 2장·9줄, 최대 4페이지, 화면 3 오른쪽 위에 `1/4` 쪽수, 넘길 수 있을 때만 라벨 표시). **이전/다음 세션 전환은 제거** — 개요에 나가(BACK) 다른 슬롯을 누른다.
- **데몬 기본 연결 BLE**: `agent_bridge.py` 를 그냥 실행하면 BLE 로만 연결한다 (USB 포트를 잡지 않아 시리얼 모니터·업로드와 충돌하지 않음). USB 만 `--transport usb`, USB 우선 `--transport auto`. BLE 신호는 서명 키가 필요하므로 처음 한 번은 USB 로 연결해 키를 등록한다.
- **버그 수정 — 상세 화면이 멈추던 문제**: DeskStreamCore `ds::utf8CharLen` 이 남은 길이를 `uint8_t` 로 잘라 비교해 256 의 배수가 남으면 0 을 반환했고, 줄바꿈 계산이 무한 루프에 빠졌다 (DeskStreamCore 0.6.1 에서 수정, 회귀 테스트 추가).
- 크기: 906,015 B (69%). 테스트: 데몬 51건, 펌웨어 호스트 테스트(1,728바이트 상세 메시지 해석 추가). 웹 플래셔 배포본 0.6.0 갱신.

## [v0.5.0] - 2026-11-10
### ✨ 설정 파일로 음소거·OLED 밝기 · 상세 화면 BTN2 = 세션 닫기
- **음소거·밝기 설정**: 설정 파일 `[device]` 의 `mute`(true/false) · `brightness`(1~100 %) 를 데몬이 `dev` 메시지로 장치에 보내고, 장치는 NVS 에 저장해 데몬이 없어도 유지한다. 밝기를 낮춰 OLED 번인을 줄일 수 있다. 값이 범위 밖이면 설정 오류로 보고 장치는 이전 값을 유지.
- **상세 화면 BTN2 = 세션 닫기(CLOSE)**: 보던 세션을 장치 슬롯에서 지운다 (승인 대기는 터미널 결정으로 넘김, 살아 있는 세션은 다음 이벤트에 다시 생김). 장치 버튼으로 음소거를 켜고 끄던 기능은 제거 (사용자 결정).
- 크기: 736,615 B (56%). 테스트: 데몬 51건, 펌웨어 dev 해석. 웹 플래셔 배포본 0.5.0 갱신.

## [v0.4.0] - 2026-11-10
### ✨ P4 — BLE 무선 연결 · 서명 · 트레이 앱 · 웹 플래셔
- **BLE UART**: 펌웨어가 USB 와 BLE("DeskStream Agent", NimBLE) 양쪽에서 같은 JSON Lines 를 받는다. 데몬은 `--transport auto`(기본: USB 우선, 없으면 BLE, BLE 중 USB 가 꽂히면 USB 로) · `usb` · `ble`.
- **BLE 서명 (보안)**: USB 로 처음 연결하면 데몬이 32바이트 키를 만들어(`~/.deskstream/device_key`, 600) 장치 NVS 에 등록 — 키 등록은 USB 에서만 받는다. BLE 연결마다 nonce, BLE 로 오는 버튼·승인 신호는 HMAC-SHA256 서명 + 증가 카운터가 맞을 때만 수락 (가짜 장치·변조·재전송 거부). 키 없는 장치는 승인 화면에 `PAIR VIA USB`.
- **who/hello**: USB 연결 시 데몬이 `who` 를 보내 이미 켜져 있던 장치도 키 id(kid)를 알려 준다 (실기 중 발견해 추가).
- **트레이 앱** `agent_bridge.py tray`: 메뉴 막대 아이콘 색(회색·초록 USB·파랑 BLE·주황 승인 대기), 상태·설정 파일 열기·종료.
- **Windows 이식성**: 설정 파일 권한 검사를 Windows 에서 제외, 트레이 설정 열기 `os.startfile`. focus·keys 는 macOS 전용, SessionStart 훅은 Git Bash 필요. Windows 실기 미검증.
- **웹 플래셔 배포본**: `firmware/Agent_Monitor/` 추가 (13번째 프로젝트), `--check` 통과.
- 크기: 735,611 B (56%, NimBLE 포함). 테스트: 데몬 43건(서명 위조·재전송·카운터·다른 키·새 연결·BLE 키 등록 거부 포함).
- 실기 확인: USB 키 등록, BLE 전용 연결에서 서명된 승인·상세 화면·PC 명령, 트레이(아이콘 색·메뉴·설정 열기), **데스크톱 앱(Code 탭) 세션 훅 수신**. 위조 신호 거부는 단위 테스트로만 확인. 데스크톱 앱에서 권한 요청 시 앱 대화상자와 장치의 동시 대기는 미확인.

## [v0.2.0] - 2026-11-10
### ✨ P2 — 장치 버튼으로 권한 승인/거절
- **승인 화면**: 권한 요청이 오면 4화면이 한 장의 승인 화면으로 바뀐다 — 머리줄(APPROVE? · 세션 · 도구 · n/q + 대기 시간, 반전 깜빡임), 명령 요약 2줄, 버튼 라벨. BTN1 승인 · BTN2 다음 요청 · BTN3 거절 · BTN4 나중에(터미널에 맡김). 새 요청 직후 0.7초는 버튼 무시.
- **데몬 `approvals.py`**: 권한 요청 대기열. PermissionRequest 응답을 최대 290초(훅 timeout 300초) 붙잡고 장치 결정을 기다린다. 장치 미연결·시간 초과·나중에 → 빈 응답(터미널 결정). 자동 허용·자동 거절 없음.
- **터미널 선결정 정리**: 같은 세션의 PostToolUse(같은 도구·입력) 또는 UserPromptSubmit·Stop·StopFailure·SessionEnd 가 오면 장치 승인 화면을 닫는다.
- 프로토콜: `perm`(데몬→장치), `decide`(장치→데몬) 추가. 시리얼 줄 버퍼 256 → 512 B.
- 크기: 427,896 B (32%). 테스트: 데몬 27건(승인 대기열·결정·시간 초과·선결정 정리), 펌웨어 perm 해석.
- 실기 확인: 실제 Claude Code 세션에서 APPROVE(실행됨) · DENY(실행 안 됨) · LATER(터미널 대화상자로) 3가지.

## [v0.1.0] - 2026-11-10
### ✨ 첫 버전 — P1 상태 표시
- **PC 데몬 `bridge_py/agent_bridge.py`**: Claude Code HTTP 훅(127.0.0.1:9230)을 받아 세션 상태를 USB 시리얼(JSON Lines)로 DeskStream에 보낸다. 모든 훅에 즉시 빈 응답 → 데몬·장치가 꺼져 있어도 Claude Code 동작에 영향 없음.
  - 세션 상태: idle / think / run / approve / input / done / error. 세션 4개까지 OLED 슬롯 배정.
  - P0 관찰 반영: SessionStart 는 curl command 훅(http 훅 미실행), `agent_type` 빈 SubagentStop 무시, 완료 뒤 `idle_prompt` 무시.
  - 훅 설정: `settings`(claude --settings 용 출력) · `install-hooks` · `uninstall-hooks`(기존 훅 보존·백업).
  - 시리얼 쓰기 timeout 1초 + 송신 스레드 한 곳에서만 쓰기 (쓰기가 막혀 데몬이 멈추던 문제를 pty 테스트에서 발견해 수정).
- **펌웨어**: OLED 1장 = 세션 1개. 상태 아이콘·애니메이션, 승인/입력 대기 반전 깜빡임, 완료 테두리, 경과 시간, 알림음(완료·주의·오류), PC 링크 끊김 표시. 버튼 짧게 = 완료 확인, 길게 = 데몬 전달(P3 예정).
- 크기: 425,372 B (32%).
- 테스트: 데몬 단위 테스트 16건(P0 실제 훅 기록 재생 포함), 펌웨어 상태 해석 호스트 테스트, pty 가짜 장치 종단 간 테스트(훅 응답 1ms 미만).
- 실기 확인: 데모 세션 4개 화면·버튼, 실제 Claude Code 세션(시작 → 실행 → 승인 대기 → 터미널 승인 → 완료).
