# P0 스파이크 결과 — 무선 측정 기능 검증

- 일시: 2026-11-11 · esp32 코어 **3.3.12** · NimBLE-Arduino 2.5.0 · U8g2 2.36.19 · DeskStreamCore 0.6.1
- 보드: DeskStream (ESP32-C3 SuperMini) · 장소: 사무실 (AP 9~18개 보이는 환경)
- 스케치: [`wa_spike/wa_spike.ino`](./wa_spike/wa_spike.ino) — 부팅 시 T1~T4 1회, 이후 T5 순환. 결과는 시리얼 115200
- 빌드: `PartitionScheme=huge_app` + 스케치 폴더의 DeskStream 공통 `partitions.csv` (app0 2.5MB)

## 1. WiFi 스캔 (T1·T2)

| 방식 | 채널당 | 소요 | 찾은 AP (2회) |
|:--|:--|:--|:--|
| 액티브 | 120ms | **2.29~2.35s** | 14 / 9 |
| 액티브 | 60ms | 1.75s | 10 / 10 |
| 패시브 | 300ms | 4.21s | 15 / **18** |

- 국가 코드 `esp_wifi_set_country_code("KR", true)` → `cc=KR schan=1 nchan=13` ✅ (12·13 채널에서 패킷 수신 확인, 해당 채널 AP는 이 환경에 없음)
- 한 번 스캔할 때마다 AP 수가 9~18개로 크게 흔들린다 (약한 AP −88dBm 이하는 들쭉날쭉).
- 한글 SSID(`1409호`, `G밸리 기업시민청_2.4G`)는 UTF-8 그대로 들어온다. 숨김 SSID는 빈 문자열.

## 2. 프로미스큐어스 채널 순회 (T3)

| 채널당 머무는 시간 | 한 바퀴(13채널) | 채널당 프레임 수 |
|:--|:--|:--|
| 150ms | 1.95s | 1~11개 |
| 500ms | 6.5s | 2~29개 |

- 동작은 정상: 채널을 바꿔 가며 관리(비콘 등)·데이터 프레임이 집계되고, 비콘 수가 그 채널 AP 수와 대략 맞는다.
- **제어 프레임은 0** — `FILTER_MASK_ALL`만으로는 안 들어온다. 필요하면 `esp_wifi_set_promiscuous_ctrl_filter()`를 따로 설정해야 한다.
- 이 환경은 트래픽이 적어(초당 수십 프레임) 150ms 집계는 한 자리 수라 **통계적으로 거의 의미가 없다**.
  "바쁜 채널이 뚜렷하게 보이는가"는 부하(영상 스트리밍 등)를 걸고 P3에서 다시 확인해야 한다.

## 3. BLE 패시브 스캔 (T4, NimBLE, 3초)

- 15~17개 기기. 이 중 **랜덤 주소 12개(75%)**, Apple(`0x004C`) 제조사 데이터가 다수. 이름은 거의 없음(패시브 스캔이라 스캔 응답 미수신).
- −70dBm보다 센 기기 8개 → 거리 구간 표시에 쓸 만한 분포.

| BLE 스택 (WiFi 스캔 포함 최소 스케치) | 바이너리 | WiFi만 대비 |
|:--|:--|:--|
| WiFi만 | 930,608 B | — |
| **NimBLE-Arduino** | 1,154,288 B | **+224KB** |
| 코어 내장 BLE (Bluedroid) | 1,192,384 B | +262KB |

## 4. 순환 동작 (T5: WiFi 액티브 120ms → 순회 150ms → BLE 3s)

- 한 주기 **7.26~7.30s** 로 안정 (8회 이상). 단계별 2.3s / 1.95s / 3.0s.
- 힙: 부팅 214KB → WiFi 켬 160KB → WiFi+BLE 켬 **89KB**, 최소 74KB (첫 측정은 LovyanGFX 캔버스 포함 84KB). 계획한 테이블(약 11KB)에 충분.
- 리셋·멈춤 없음.

## 5. 플래시

- 스파이크 전체(WiFi + NimBLE + DeskStreamCore + 갈무리7 한글 폰트 166KB) = **1,370,064 B**
  (처음 LovyanGFX 캔버스로 그렸을 때 1,399,504 B — 한글 표시 방식 변경 후 29KB 줄어듦)
  → 기본 파티션(1.25MB)에 안 들어감. **DeskStream 공통 `partitions.csv`(2.5MB) 필수**.

## 6. 미확인

- [x] **OLED 한글 표시** — Agent_Monitor와 같은 방식(화면별 U8g2 + 갈무리7 `drawUTF8` + `display.push()`).
  부팅 문구·SSID 목록(`1409호` 등)이 깨지지 않는 것을 보드에서 확인 (2026-11-11).
- [x] **화면 경계 이어 그리기** — 512px 가상 좌표에서 화면 i는 x를 `-128*i` 옮겨 그린다. 처음 확인 때는
  경계(x=128·256·384)에 걸친 글자가 없어 확인되지 않아, 부팅 2초 뒤 8초간 경계 테스트 화면을 넣었다.
  - 1차 보드 확인: **4화면을 잇는 사선이 OLED1에만 표시됨.** U8g2 좌표가 부호 없는 16비트라 음수 x를 넘기면
    `drawLine`이 양 끝을 잘못 비교한다. PC에서 U8g2 C 소스로 같은 화면을 그려 재현했고, 글자·상자·가로선은
    음수 x에서도 경계에 걸쳐 정상으로 그려지는 것을 확인했다.
  - 수정: 직선은 `drawLine512()`로 화면 범위에 먼저 잘라 0~127 좌표만 넘긴다. PC 재현과 **보드에서
    4화면에 이어지는 것 확인** (2026-11-11).
- [ ] 바쁜 채널에서 순회 집계가 뚜렷이 커지는지 (P3)
