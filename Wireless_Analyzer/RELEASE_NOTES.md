# Release Notes - Wireless_Analyzer

## [0.5.0] - 2026-11-11
### 🗂️ 요약 화면 · 설정 저장 · 부팅 화면 (PLAN P5)
- 6번째 모드 **요약**: 화면마다 타일 — WiFi AP 수·사용 채널 / 추천 채널·가장 혼잡한 채널 / 가장 센 AP / BLE 기기 수·거리 구간.
  이 화면에서는 WiFi 스캔 → 채널 순회 → BLE 스캔을 모두 돈다.
- `channelScore()`로 추천 점수 계산을 공통화하고 `busiestChannel()`(비용 + 활동량 벌점이 가장 높은 채널) 추가.
- **마지막 모드 · 밝기 · 뒤집기를 NVS에 저장** (`ds::ConfigStore`, 네임스페이스 `wanalyzer`, 5초 지연 저장).
- 버튼: BTN1 길게 = 화면 180° 뒤집기(패널 `setFlip` + 화면 순서 반대로 그리기), BTN4 길게 = 밝기 단계(10 → 50 → 128 → 255).
- **부팅 화면**: 화면마다 `Wireless` · `Analyzer` · `2.4GHz 무선 환경 분석기` · `WiFi / BLE` + 버전, 최소 1.5초.
  이전 부팅 화면은 512px 가운데(OLED2·3 경계)에 글자를 그려 쪼개졌고, 곧바로 첫 화면이 덮어써 거의 보이지 않았다.
- 시리얼 디버그 `f` = 화면 뒤집기.
- 호스트 테스트 추가(채널 점수·가장 혼잡한 채널). 크기 약 1.40MB.
  보드에서 요약 화면, 뒤집기 후 리셋해도 요약 모드·뒤집힘 유지를 화면 덤프로 확인. 부팅 화면·밝기 단계·버튼 길게 누르기를 실기에서 확인.
- **웹 플래셔 배포본 추가** (PLAN P6): `firmware/projects.json`(order 14)·`firmware/Wireless_Analyzer/`·`manifest.json`, `--check` 통과.

## [0.4.0] - 2026-11-11
### 🔵 BLE 기기 화면 (PLAN P4)
- 5번째 모드 **BLE 기기**: 근처 기기 수(최근 30초 동안 본 서로 다른 주소 수)·거리 구간별 수(가까움/중간/멂), 기기 수 추이,
  신호가 센 순서 6줄(이름 · 제조사 · RSSI). 기기 주소는 표시하지 않고, 어떤 정보도 장치 밖으로 저장·전송하지 않는다.
- NimBLE **액티브 스캔**(3초) — 이름은 대부분 스캔 응답에 있어서. 이름은 한 번 받으면 다음 스캔에서 빠져도 유지.
- BLE 스캔은 BLE 화면에서만, 그동안 WiFi 스캔은 쉰다 (`scheduler`가 WiFi·순회·BLE를 번갈아 실행 — 다른 화면의 WiFi 주기는 그대로).
- 버그 수정: "스캔 중..." 안내를 512px 가운데(OLED2·3 경계)에 그려 글자가 쪼개졌다 → OLED2 가운데로.
- 호스트 테스트 추가(BLE 테이블·UTF-8 자르기·제조사 이름). 크기 약 1.40MB (NimBLE +23만 바이트).
  보드에서 BLE 화면(18대, Apple 다수 — 이름 없음 `-`)·150초 연속 동작·WiFi 화면 복귀를 화면 덤프로 확인.
  첫 시험 때 BLE 화면에서 보드 응답이 끊기고 포트가 바뀌었으나 다시 올린 뒤 재현되지 않음. 이름을 광고하는 기기가 표시되는지는 미확인.

## [0.3.2] - 2026-11-11
### 🔁 바쁜 정도 지표를 "사용률"에서 "활동량(초당 제어·데이터 프레임)"으로
- 부하 측정(ch10 공유기에 영상 스트리밍): 초당 프레임은 92 → 329로 늘었지만 0.3.0의 사용률(전송 시간 합)은 5% 안팎 그대로였다.
  진단해 보니 ESP32-C3(1스트림)는 2스트림 데이터 프레임(MCS 8~15)을 해독하지 못해 스트리밍 본체가 보이지 않고, 그 응답인 Block ACK만 보였다.
- 이제 채널마다 **제어·데이터 프레임 수/초**를 센다. 관리 프레임(비콘 등)과 오류 프레임(`rx_state ≠ 0`)은 뺀다.
  같은 부하에서 ch10 = 153프레임/s, 나머지 채널 0~6 — 부하 채널이 확연히 구분된다.
- 혼잡도 화면 오른쪽 막대 = 활동량(0~400프레임/s), 추천 이유 `활동 n/s`. 추천은 100프레임/s마다 +3dB.
- 전송 시간 추정 코드(`phyRateKbps`·`frameAirtimeUs`)는 쓰지 않게 되어 지웠다. 시리얼 `t` 출력은 `fps`·`sweeps`만.
- 호스트 테스트 통과. 크기 약 1.17MB. 보드에서 부하 중 화면·`t` 출력 확인, 부하를 끈 뒤 ch10이 153 → 10~66프레임/s로 내려가는 것 확인.

## [0.3.1] - 2026-11-11
### 🏷️ 모드 이름 표시 · 혼잡도 화면 AP 수 0 표시
- 화면에 모드 이름이 없어 문서의 "채널 혼잡도 모드"가 어느 화면인지 알 수 없었다. 모드를 바꾸면(부팅 직후 포함) OLED2 가운데에
  `2/4 채널 혼잡도`처럼 번호와 이름을 1.5초 띄운다.
- 혼잡도 화면 막대 위 AP 수를 0일 때도 쓴다 — 숫자가 없으면 빠진 건지 0인지 구분이 안 됐다. 0인데 막대가 있으면 옆 채널 겹침 때문이다.
- 보드에서 화면을 버퍼 덤프로 확인.

## [0.3.0] - 2026-11-11
### 📊 채널 사용률 실측 (PLAN P3)
- 혼잡도 모드에서 WiFi 스캔 사이에 채널 1~13을 150ms씩 순회하며(프로미스큐어스) 받은 프레임의 **전송 시간**을 추정해
  채널 사용률(전파가 쓰인 시간 비율)을 잰다. 바퀴마다 지수 평균(새 값 30%). 제어 프레임(ACK·RTS·CTS)도 함께 받는다.
- 혼잡도 화면: 채널마다 왼쪽 = 비용 막대, 오른쪽 = 사용률 막대(속 빈, 0~100%). 오른쪽 위에 범례, 추천 이유에 사용률 추가.
- 추천 채널에 실측 사용률 × 10dB를 더한다 (30%면 +3dB).
- `scheduler` — 스캔과 순회를 번갈아 실행. 순회는 혼잡도 모드에서만, 일시정지·모드 이동 시 바로 멈춘다. 다른 모드의 스캔 주기는 그대로.
- 시리얼 디버그 `t` = 채널별 사용률·초당 프레임·측정 횟수.
- 호스트 테스트 추가(전송 속도·전송 시간·평균·사용률 반영 추천). 크기 약 1.17MB.
  보드에서 화면·`t` 출력 확인 (사무실: 사용률 0.3~11%). 부하를 건 채널이 높아지지 않아 0.3.2에서 지표를 바꿨다.

## [0.2.1] - 2026-11-11
### 🧭 추천 채널 알고리즘 개선
- 0.2.0까지는 1·6·11 중 막대(겹침 가중 신호 합)가 가장 낮은 채널만 추천해서, 막대가 가장 낮은 채널과 추천이 달랐고
  같은 채널 겹침과 옆 채널 겹침을 같은 무게로 계산했다.
- 이제 채널마다 "그 채널에 둘 때의 비용"을 계산한다 — 같은 채널의 센 AP(−82dBm 이상)는 시간 나눠 쓰기(신호 그대로),
  일부 겹치는 AP와 약한 같은 채널 AP는 잡음(겹침 비율 × 2배). 추천은 1~13 전체에서 비용이 가장 낮은 채널이고,
  1·6·11 밖 채널에는 3dB 벌점을 준다. 혼잡도 막대도 같은 비용으로 그린다.
- 혼잡도 화면 왼쪽 위에 추천 이유를 쓴다: `추천 ch5 (같은 채널 1 / 겹침 15)`.
- 호스트 테스트 추가 (1·6·11에 몰리면 1·6·11 추천, 흩어지면 밖 채널 추천, 약한 같은 채널 AP는 잡음). 보드에서 화면을 버퍼 덤프로 확인.

## [0.2.0] - 2026-11-11
### 📶 AP 목록·추적 (PLAN P2)
- AP마다 최근 60회 스캔의 RSSI를 링버퍼에 기록한다 (그 스캔에서 안 보이면 빈칸).
- **AP 목록** 모드: RSSI 순 6줄 — SSID · 채널 · RSSI · 스파크라인. 스파크라인은 줄마다 그 AP의 최소~최대로 확대(최소 10dB 폭) —
  처음 고정 범위(−95~−30dBm)로 그렸더니 7px 높이에서 거의 평평해 보여 바꿨다.
- **AP 추적** 모드: 선택 AP의 현재 RSSI(갈무리7 굵게)·세기 막대·최고/평균, 최근 190회 그래프. 이 모드에서는 그 AP의 **채널만** 반복 스캔해
  약 0.15초마다 갱신하고, 그동안 다른 채널 AP는 기록·정리하지 않는다.
- **추적 부저**(기본 꺼짐, BTN3 길게): −90dBm 1초 ~ −30dBm 0.1초 간격으로 삑. 마지막 유효 기록이 2초보다 오래되면 멈춘다.
- 버튼: BTN3/BTN4 짧게 = 목록·추적에서 이전/다음 AP 선택. 시리얼 디버그 `n` = 다음 AP.
- 호스트 테스트 통과. 크기 약 1.16MB. 보드에서 네 모드 화면을 버퍼 덤프로 확인.
  버튼(AP 선택·부저 토글)·부저 소리·이동하며 그래프가 따라 변하는 것을 실기에서 확인.

## [0.1.0] - 2026-11-11
### 📡 첫 펌웨어 — WiFi 스캔과 채널 화면 (PLAN P1)
- 비동기 WiFi 액티브 스캔(채널당 120ms, 국가 코드 KR = 채널 1~13)을 반복하고, BSSID별 AP 테이블에 60초 동안 유지한다.
- **채널 스펙트럼** 모드: AP마다 ±2채널 폭 언덕을 RSSI 높이로 겹쳐 그리고, 센 AP 4개까지 SSID(갈무리7 한글 글꼴)를 겹치지 않게 표시.
- **채널 혼잡도** 모드: 겹침 비율 (22 − 5d) / 22 로 가중한 채널별 신호 합 막대 + AP 수, 1·6·11 중 추천 채널 반전 표시.
- 버튼: BTN1/BTN2 짧게 = 이전/다음 모드, BTN2 길게 = 스캔 일시정지/재개.
- 4화면을 512px 한 장처럼 그리는 `canvas512.h` — U8g2 좌표가 부호 없는 16비트라 음수 x에서 직선이 깨지는 문제(P0 발견)를 화면별 자르기로 처리.
  채널 중심을 화면 경계에서 16px 이상 떼어 채널 번호가 쪼개지지 않게 배치.
- 시리얼 디버그: `d` = 4화면 버퍼 덤프, `m` = 다음 모드.
- 호스트 테스트 통과. 크기 약 1.15MB (Huge APP + 공통 `partitions.csv`).
  보드에서 두 모드 화면을 버퍼 덤프로 확인, 버튼 동작(모드 전환·일시정지)을 실기에서 확인.
