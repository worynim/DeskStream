# 📡 Wireless_Analyzer: 2.4GHz 무선 환경 분석기 (v0.5.0)

ESP32-C3의 WiFi·BLE 무선부 자체를 측정 도구로 써서 주변 2.4GHz WiFi·BLE 환경을 DeskStream 512x64 화면에 보여주는 단독 장치입니다.
공유기에 접속하지 않고, PC·인터넷 연결도 필요 없습니다.

> 개발 계획과 진행 상태는 [PLAN.md](./PLAN.md), 측정 검증 결과는 [p0_spike/RESULTS.md](./p0_spike/RESULTS.md)를 참고하세요.
> 화면 6개(채널 스펙트럼·채널 혼잡도·AP 목록·AP 추적·BLE 기기·요약). [웹 플래셔](https://worynim.github.io/DeskStream/)에서 "무선 환경 분석기"를 골라 바로 설치할 수 있습니다.

## 기능

| 모드 | 내용 |
|:--|:--|
| **채널 스펙트럼** | AP마다 ±2채널 폭 언덕을 신호 세기(−95~−30dBm) 높이로 겹쳐 그립니다. 센 AP 4개까지 SSID(한글 포함)를 표시하고, 왼쪽 위에 AP 수를 표시합니다. 숨김 SSID는 `(숨김)` |
| **채널 혼잡도** | 채널 1~13마다 왼쪽 = "그 채널에 공유기를 둘 때의 비용" 막대, 오른쪽 = **실측 활동량** 막대(속 빈, 0~400프레임/s), 막대 위에 그 채널을 중심으로 쓰는 AP 수(0 포함 — 0인데 막대가 있으면 옆 채널 겹침 때문). 비용이 가장 낮은 채널을 **추천 채널**로 채널 번호를 반전하고, 왼쪽 위에 이유를 씁니다 (예: `추천 ch5 (같은 채널 1 / 겹침 16 / 활동 0/s)`) |
| **AP 목록** | 신호가 센 순서로 6줄: SSID · 채널 · RSSI · 최근 60회 RSSI 스파크라인(줄마다 그 AP의 최소~최대로 확대, 최소 10dB 폭 — 안 보인 스캔은 끊김). `>`가 선택한 AP |
| **AP 추적** | 선택한 AP 하나의 현재 RSSI(굵게)·세기 막대·최근 60회 최고/평균과 최근 190회 RSSI 그래프(−40·−60·−80dBm 점선). 이 모드에서는 **그 AP의 채널만** 반복 스캔해 약 0.15초마다 갱신합니다. 부저를 켜면 신호가 셀수록 빠르게 삑삑(−90dBm 1초 ~ −30dBm 0.1초 간격) — 공유기 위치 찾기용 |
| **BLE 기기** | OLED1: 근처 BLE 기기 수(최근 30초 동안 본 서로 다른 주소 수)와 거리 구간별 수(가까움 −60dBm보다 셈 / 중간 / 멂 −80dBm보다 약함). OLED2: 기기 수 추이. OLED3·4: 신호가 센 순서로 6줄 — 이름(광고한 기기만, 없으면 `-`) · 제조사(Apple·Samsung 등, 모르면 회사 ID) · RSSI. **기기 주소는 표시하지 않습니다.** 이 화면에서만 BLE 스캔(액티브 3초)을 반복하고 그동안 WiFi 스캔은 쉽니다 |
| **요약** | 화면마다 타일 하나: WiFi AP 수·사용 채널 수 / 추천 채널·가장 혼잡한 채널 / 가장 센 AP(SSID·채널·RSSI) / BLE 기기 수·거리 구간. 이 화면에서는 WiFi 스캔 → 채널 순회 → BLE 스캔을 모두 돌려 한 바퀴 약 7초마다 갱신됩니다 |

- WiFi 액티브 스캔(채널당 120ms, 한 번 약 2.3초)을 쉬지 않고 반복합니다. 스캔 중에도 버튼·화면은 멈추지 않습니다.
- 처음 스캔이 끝나면 가장 센 AP가 선택됩니다. 선택한 AP가 목록에서 사라져도 추적 화면은 마지막 정보를 유지하고 `신호 없음`을 표시합니다.
- 한 번 본 AP는 60초 동안 목록에 남깁니다 (스캔마다 약한 AP가 보였다 안 보였다 하는 것을 흡수).
- **BLE 개인정보**: 주변 사람들의 기기 정보라 이름·제조사·RSSI만 화면에 보여주고, 주소는 같은 기기를 한 번만 세는 데만 씁니다.
  어떤 정보도 장치 밖으로 저장·전송하지 않습니다 (시리얼 디버그에도 출력하지 않음). 휴대폰 상당수(특히 Apple)는 이름을 광고하지 않아 `-`로 보입니다.
- **채널 비용**: 같은 채널의 센 AP(−82dBm 이상)는 서로 번갈아 보내므로 "시간 나눠 쓰기" 비용(신호 세기 그대로)으로,
  일부만 겹치는 옆 채널 AP와 약한 같은 채널 AP는 충돌을 일으키는 잡음이라 겹침 비율 × 2배로 계산합니다.
  추천은 1~13 전체에서 고르되 1·6·11 밖 채널에는 3dB 벌점을 줍니다 — AP가 1·6·11에 몰려 있으면 1·6·11 중에서,
  흩어져 있어 다른 채널이 확실히 한산할 때만 그 채널을 추천합니다. 실측 활동량이 있으면 100프레임/s마다 3dB를 더합니다.
  자세한 근거는 [PLAN.md](./PLAN.md) §3.3.
- **채널 활동량 실측**: 혼잡도 모드에서만, 스캔 사이에 채널 1~13에 150ms씩 머물며 받은 **제어·데이터 프레임 수/초**를 셉니다
  (한 바퀴 약 2초, 바퀴마다 평균). 비콘 같은 관리 프레임과 오류 프레임은 뺍니다. 그래서 이 모드에서는 AP 정보 갱신이 약 4.3초 간격이 됩니다.
  ESP32-C3는 스트림이 1개라 휴대폰·공유기의 대용량 전송 본체(2스트림)는 해독하지 못하고, 그 응답(Block ACK 등)으로 바쁜 정도를 봅니다 —
  그래서 "몇 %를 쓰는가"가 아니라 상대적인 활동량입니다. 영상 스트리밍 중인 채널이 153프레임/s, 나머지가 0~6으로 확연히 구분됐습니다.
  근거는 [PLAN.md](./PLAN.md) §3.5.
- **측정 한계**: WiFi 비콘을 보내는 AP만 보입니다. 전자레인지·무선 마우스 같은 비-WiFi 간섭은 측정할 수 없고,
  채널 비용은 "주변 AP가 얼마나 세게 겹치는가"의 추정치이지 실제 트래픽량이 아닙니다.

## 버튼

| 버튼 | 짧게 | 길게 |
|:--|:--|:--|
| BTN1 | 이전 모드 | 화면 180° 뒤집기 (보드를 거꾸로 세울 때) |
| BTN2 | 다음 모드 | 스캔 일시정지/재개 (오른쪽 위에 `일시정지`) |
| BTN3 | 목록·추적: 이전(더 센) AP 선택 | 추적: 부저 켜기/끄기 (기본 꺼짐) |
| BTN4 | 목록·추적: 다음(더 약한) AP 선택 | 밝기 단계 (10 → 50 → 128 → 255) |

모드 순서: 1 채널 스펙트럼 → 2 채널 혼잡도 → 3 AP 목록 → 4 AP 추적 → 5 BLE 기기 → 6 요약 → (처음으로).
모드를 바꾸면(부팅 직후 포함) OLED2 가운데에 `2/4 채널 혼잡도`처럼 모드 이름이 1.5초 동안 뜹니다 (`5/6 BLE 기기` 등). 추적 모드에 들어가거나 AP를 바꾸면 추적 그래프를 새로 시작합니다.

**마지막 모드 · 밝기 · 뒤집기**는 저장돼 다시 켜도 유지됩니다(바꾼 뒤 5초 후 저장). 추적 부저는 저장하지 않아 켤 때마다 꺼진 상태로 시작합니다.
켜면 부팅 화면(`Wireless` `Analyzer` …, 버전)이 1.5초 동안 보입니다.

## 시리얼 디버그 (115200)

| 입력 | 동작 |
|:--|:--|
| `d` | 4화면 버퍼를 `DUMP <화면> <1024바이트 hex>` 줄로 출력 (화면 확인용) |
| `m` | 다음 모드 (BTN2 짧게와 같음) |
| `n` | 다음 AP 선택 (BTN4 짧게와 같음, 목록·추적 모드) |
| `f` | 화면 180° 뒤집기 (BTN1 길게와 같음) |
| `t` | 채널별 실측 활동량·측정 횟수 출력 (`TRAFFIC ch10 fps= 152.8 sweeps=9`) |

## 파일 구성

| 파일 | 내용 |
|:--|:--|
| `Wireless_Analyzer.ino` | setup/loop, 버튼, 모드 전환, 설정 저장(NVS), 시리얼 디버그 |
| `config.h` | 버전, 스캔·화면 상수 |
| `scheduler.cpp/.h` | 라디오 시분할 — WiFi 스캔, 채널 순회 측정, BLE 스캔을 번갈아 실행 |
| `ble_scan.cpp/.h` | NimBLE 액티브 스캔 → BLE 기기 테이블 갱신 |
| `ble_table.cpp/.h` | 순수 로직 — BLE 기기 테이블(주소로 중복 제거, 30초 유지), 거리 구간, 제조사 이름 |
| `wifi_scan.cpp/.h` | 비동기 WiFi 스캔(전체 또는 채널 하나) → AP 테이블·RSSI 기록 갱신 |
| `wifi_sniff.cpp/.h` | 프로미스큐어스 채널 순회 → 채널별 제어·데이터 프레임 수 |
| `traffic.cpp/.h` | 순수 로직 — 채널 활동량(초당 프레임) 평균 |
| `analysis.cpp/.h` | 순수 로직 — AP 테이블·RSSI 기록, 채널 비용, 추천·가장 혼잡한 채널, 부저 간격, 스파크라인 범위, 직선 자르기 |
| `canvas512.h` | 4화면을 512x64 한 장처럼 그리는 도우미 |
| `ui.cpp/.h` | 화면 모드 렌더러 |
| `u8g2_font_galmuri7_kr.h` | 갈무리7 한글 글꼴 (Agent_Monitor와 같음, SIL OFL 1.1) |
| `test/test_analysis.cpp` | `analysis` · `traffic` · `ble_table` 호스트 단위 테스트 |
| `p0_spike/` | 측정 기능 검증용 임시 스케치와 결과 |

## 빌드

- 필요 라이브러리: **DeskStreamCore**(저장소 `libraries/`, `bash scripts/link-arduino-lib.sh`), **U8g2**, **NimBLE-Arduino**(2.5.0에서 확인)
- 보드: `esp32:esp32:makergo_c3_supermini`, CPU 160MHz, **Partition Scheme = Huge APP** (스케치 폴더의 DeskStream 공통 `partitions.csv` 사용)

```bash
arduino-cli compile --fqbn "esp32:esp32:makergo_c3_supermini:CDCOnBoot=default,CPUFreq=160,PartitionScheme=huge_app" Wireless_Analyzer
```

호스트 테스트 (저장소 루트에서):

```bash
g++ -std=c++17 -IWireless_Analyzer Wireless_Analyzer/test/test_analysis.cpp Wireless_Analyzer/analysis.cpp Wireless_Analyzer/traffic.cpp Wireless_Analyzer/ble_table.cpp -o /tmp/test_analysis && /tmp/test_analysis
```
