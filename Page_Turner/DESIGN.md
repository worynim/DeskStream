# Page_Turner 설계서

작성일: 2026-11-20 · 상태: **1.0.0 구현됨** (아래 결정은 구현과 실기 확인 중 바뀐 내용을 반영)

## 1. 목적

DeskStream 보드를 손에 쥐는 **BLE 페이지 터너**로 만든다. 웹소설·웹툰·숏폼을 볼 때 엄지로 버튼을 눌러 페이지를 넘기고, 스마트폰 카메라 셔터와 PC 발표 슬라이드 넘김에도 쓴다.

- 1차 대상: **Android 폰**. iOS는 나중에 추가한다.
- 전원: 지금은 사용자가 배터리를 외부에 단다. **V2 하드웨어**에서 배터리를 내장한다.
- 근거: 2026-11-20 시험 펌웨어(`Page_Turner.ino` 현재 상태)로 앱별 입력 방식과 기본값을 실기기에서 확인했다 (§4).

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 앱 이름별 모드 7개를 BTN3으로 고르고, BTN1/BTN2로 이전·다음(또는 위·아래)을 보낸다.
- 모드별 설정값과 공통 설정을 버튼 메뉴로 바꾸고 **NVS에 저장**해 전원을 꺼도 유지한다.
- 폰과 PC를 함께 기억하고, 버튼으로 연결 기기를 바꾼다.
- 입력이 없으면 **1분 뒤 화면을 끄고, 5분 뒤 슬립**에 들어가 배터리를 아낀다.
- 웹 플래셔에 등록한다.

**비목표 (이번 버전에서 하지 않음)**
- Wi‑Fi 웹 설정 페이지 (버튼 설정만 둔다).
- 사용자가 모드를 추가·삭제·이름 변경하는 기능 (모드 목록은 펌웨어에 고정).
- 배터리 잔량 표시 (V2 하드웨어에서).
- iOS 전용 대응 (§9 참고).
- 터치 흉내·마우스 드래그 (시험에서 커서 위치에 따라 오동작해 제외).

**실패 조건 (동작은 해도 실패로 본다)**
- 버튼을 눌렀는데 신호가 늦게 가거나 한 번 누름이 두 번 넘어간다.
- 전원을 껐다 켜면 설정이 사라진다.
- 기기를 바꾼 뒤 이전 기기가 다시 연결을 가로채 원하는 기기에 연결되지 않는다.
- 화면이 꺼진 상태에서 누른 첫 버튼이 페이지를 넘긴다 (§6.4).

## 3. 제약

- 보드: ESP32-C3 SuperMini, SSD1306 128x64 × 4, 버튼 4개(GPIO 1/4/10/9), 패시브 부저(GPIO 7). [hardware.md](../hardware.md)
- 저장소 규칙: [AI_GUIDE.md](../AI_GUIDE.md) — 화면·버튼·부저·설정 저장은 `DeskStreamCore`를 쓰고 복사하지 않는다. `display.push()`로만 전송한다.
- BLE 라이브러리: **NimBLE-Arduino 2.5.0** (설치됨). DS_DECK의 `HijelHID_BLEKeyboard`는 마우스 휠을 지원하지 않아 쓰지 않는다.
- NimBLE 본딩 최대 3개 (`CONFIG_BT_NIMBLE_MAX_BONDS` 기본값).
- 빌드 크기: 약 742KB. 웹 플래셔 프로젝트 공통 레이아웃에 맞춰 DeskStream 공통 `partitions.csv`(Huge APP, app0 2.5MB)를 쓴다 — 다른 프로젝트로 바꿔 올려도 LittleFS·NVS 위치가 같다.

## 4. 시험으로 확정한 입력 방식 (Android)

| 대상 | 입력 | 결과 |
|---|---|---|
| 웹소설 (시리즈·카카오, 앱에서 볼륨 넘김 켬) | 볼륨+ / 볼륨− | 잘 됨 |
| 카메라 | 볼륨+ / 볼륨− | 셔터 동작 |
| 시리즈 웹툰 | 휠 1칸 × 10, 80ms 간격 | 잘 됨 (휠을 한 번에 크게 보내면 확 넘어가서 나쁨) |
| 카카오 웹툰 | 방향키 ↑↓ × 4, 30ms 간격 | 잘 됨 (PageUp/Down도 되지만 방향키가 나음, 휠은 화면이 팍 바뀌어 나쁨) |
| 유튜브 쇼츠 | 휠 1칸 × 3, 30ms 간격 + 커서 치우기 | 잘 됨 |
| PPT | PageUp / PageDown | 실기 미확인 (표준 동작) |
| 터치 탭·스와이프 | — | 거의 동작 안 함 (커서만 뜸) |
| 마우스 드래그 | — | 커서가 화면 끝에 닿으면 반대로 넘어가는 등 불안정 |

## 5. 접근 방식

| 안 | 내용 | 결과 |
|---|---|---|
| **A. 버튼만으로 설정하는 단독 기기** | 시험 펌웨어 구조를 DeskStream 규칙에 맞춰 정리, 설정은 NVS 저장 | **채택** — 배터리 휴대 기기에 맞고 앱별 값은 이미 확정됨 |

## 6. 동작 설계

### 6.1 HID 장치 구성 (시험 펌웨어와 동일)

하나의 BLE HID 장치에 리포트 3개: 키보드(ID 1), Consumer 미디어 키(ID 2), 마우스(ID 3, 휠만 사용 + 커서 치우기용 X 이동). 리포트 맵은 시험 펌웨어 `kReportMap` 그대로 쓴다.

### 6.2 모드 (고정 목록, BTN3으로 순환)

| # | 이름 | 신호 | BTN1 / BTN2 | 모드 설정 (기본값) |
|---|---|---|---|---|
| 1 | YouTube | 휠 | 위 / 아래 | Steps x3, Gap 30ms, Cursor Hide |
| 2 | Kakao Webtoon | 방향키 ↑↓ | 위 / 아래 | Keys x4, Gap 30ms |
| 3 | Kakao Novel | 볼륨 +/− | 이전 / 다음 | 없음 |
| 4 | Series Webtoon | 휠 | 위 / 아래 | Steps x10, Gap 80ms, Cursor Hide |
| 5 | Series Novel | 볼륨 +/− | 이전 / 다음 | 없음 |
| 6 | Camera | BTN1 볼륨+ / BTN2 딜레이 셔터 | 셔터 / 딜레이 셔터 | Timer 3s (2, 3, 5, 10s) |
| 7 | PPT | PageUp / PageDown | 이전 / 다음 | 없음 |

설정값 후보 (시험 펌웨어와 동일):
- Steps (휠 칸 수): 1, 2, 3, 4, 5, 6, 8, 10, 12, 15, 20, 25, 30
- Keys (방향키 횟수): 1, 2, 3, 4, 5, 6, 7, 8, 10, 12, 15, 20
- Gap (간격 ms): 10, 30, 50, 80, 120, 160, 200, 250
- Cursor: Hide(신호 전에 커서를 화면 오른쪽 끝으로 이동) / Show

**공통 설정** (모든 모드의 설정 메뉴 끝에 붙음)
- Beep: On / Off — 모든 부저 소리.

**Camera 모드 BTN2 = 딜레이 셔터** (사용자 결정, §10): 누르면 Timer 초를 OLED2에 크게 세고 1초마다 비프한 뒤 볼륨+로 셔터. 세는 중에 BTN2를 다시 누르거나 모드 변환·설정 메뉴로 가면 취소. *(취소 동작·Timer 값 목록은 작성자 결정)* 시험판에 구현됨.

### 6.3 버튼

| 버튼 | 일반 | 설정 메뉴 안 |
|---|---|---|
| BTN1 | 이전/위 신호 | 값 줄이기 (목록 처음에서 멈춤) |
| BTN2 | 다음/아래 신호 | 값 늘리기 (목록 끝에서 멈춤) |
| BTN3 짧게 | 다음 모드 | 취소 (바꾼 값 버림) |
| **BTN3 길게 (1초)** | **기기(슬롯) 선택 화면** (§6.5) | — |
| BTN4 | 설정 메뉴 진입 | 다음 항목, 마지막 항목에서 저장 |

- 모드 설정이 없는 모드에서도 BTN4를 누르면 공통 설정(Beep)만 나온다.
- 신호를 보내는 중(최대 30칸 × 250ms ≈ 7.5초)에도 버튼 판정이 멈추지 않아야 한다. 신호 전송은 별도 태스크에서 하고, **전송 중 들어온 BTN1/BTN2 누름은 버린다**. *(작성자 결정: 쌓아 두면 손을 뗀 뒤에도 계속 넘어가서 실패 조건에 걸림)*
- 마지막 모드는 NVS에 저장해 다음 부팅 때 그 모드로 시작한다. *(작성자 결정)*

### 6.4 화면 끄기와 슬립 (사용자 지정 시간)

| 마지막 버튼 입력 후 | 동작 |
|---|---|
| **1분** | 4화면을 끈다 (`U8G2::setPowerSave(1)`). BLE 연결은 유지한다. |
| **5분** | **딥슬립**에 들어간다. BLE 연결이 끊긴다. |

- 화면이 꺼진 상태에서 누른 **첫 버튼은 화면만 켜고 신호를 보내지 않는다** (사용자 선택).
- 딥슬립 깨우기: **BTN1(GPIO 1)·BTN2(GPIO 4)만 가능**하다. ESP32-C3의 딥슬립 GPIO 깨우기는 GPIO 0~5만 지원해서 BTN3(GPIO 10)·BTN4(GPIO 9)로는 깨울 수 없다. 깨우면 재부팅 후 마지막 기기에 자동으로 다시 연결된다 (보통 수 초). 깨운 누름은 신호를 보내지 않는다.
- 슬립에 들어가기 직전 "Sleep" 화면을 1초 띄우고, 저장 대기 중인 설정이 있으면 먼저 저장한다 (`ConfigStore::saveNow()`). *(작성자 결정)*
- 설정 메뉴 안에서 1분이 지나 화면이 꺼지면 메뉴를 취소한다. *(작성자 결정)*
- BLE 연결 상태가 바뀌어도 화면은 켜지 않는다. *(작성자 결정: 주머니 속에서 깨어나 배터리를 쓰지 않게)*
- 버튼 핀은 내부 풀업이고 누르면 LOW이므로, 딥슬립 깨우기는 LOW 레벨로 설정한다. 슬립 진입 시 버튼이 눌려 있으면 놓을 때까지 기다린다 (곧바로 깨는 것 방지).

### 6.5 연결 기기 슬롯 1~3 (사용자 요청으로 "전환 대기" 방식을 대체, 2026-11-20)

- 슬롯 3개에 기기를 하나씩 기억한다 (본딩 최대 3개와 같음). 지금 슬롯은 OLED4 이름표에 `BT1 ON` / `BT1 wait`.
- **BTN3 길게 → 기기 선택 화면**: OLED1~3 = 슬롯 1~3(`In use` / `Paired` / `Empty`), OLED4 = 취소.
  - 슬롯 버튼(BTN1~3) **짧게**: 처음엔 그 슬롯을 고르고(반전), **고른 슬롯을 한 번 더** 누르면 그 슬롯을 쓴다.
  - 슬롯 버튼 **길게**: 그 슬롯에 새 기기 페어링 대기. **기존 기기는 새 기기가 본딩되는 순간에 교체**하고, 취소·60초 경과 시 기존 기기를 그대로 쓴다 (사용자 요청).
  - **BTN4**: 취소.
- 페어링된 슬롯을 쓰면 그 기기만 연결을 받는다 — 광고를 화이트리스트(그 기기 신원 주소)로 걸러 다른 기기에는 보이지 않는다 (예전 방식은 다른 기기가 1초에 여러 번 재연결을 시도했다).
- 빈 슬롯을 쓰면 페어링 대기: 슬롯에 있는 기기는 받지 않고, 처음 본딩되는 새 기기가 그 슬롯에 들어간다. 60초 안에 새 기기가 없거나 BTN3 짧게 → 쓰던 슬롯(기존 기기)으로 돌아간다. 페어링된 기기가 하나도 없으면 카운트 없이 계속 기다린다.
- 슬롯 3개가 모두 찬 상태에서 교체하면 본딩 저장 공간이 넘친다. NimBLE 기본 처리(가장 오래된 기기 삭제) 대신 **교체 중인 슬롯의 기존 기기**를 지운다 — 이 경우에만 페어링이 실패하면 기존 기기도 다시 페어링해야 한다.
- 슬롯 표와 지금 슬롯은 NVS(`pt_slots`)에 저장. 부팅 때 본딩과 맞춘다: 본딩이 없는 슬롯은 비우고, 슬롯에 없는 본딩은 빈 슬롯에 넣는다.
- 연결이 끊기면 광고를 다시 시작한다 (`advertiseOnDisconnect(true)` — NimBLE 2.x 기본값은 꺼짐).
- **구독(CCCD) 저장 한도**: NimBLE 기본 8개는 HID 기기 2대(대당 4~5개)에서 넘쳐, 넘치면 가장 오래된 기기의 페어링을 지운다. 스케치 폴더 `build_opt.h`로 `MYNEWT_VAL_BLE_STORE_MAX_CCCDS=24`.

### 6.6 화면 (세로 방향, 화면마다 64x128)

- 회전: `DisplayConfig::rotation = U8G2_R1` — 세로로 쥐었을 때 OLED1이 위 (실기 확인 완료).
- 구성 원칙: 각 OLED는 옆 버튼의 역할을 보여준다. **맨 위 설명**(Prev page, Change mode, Settings 등) + 가운데 아이콘/내용 + **맨 아래 테두리 이름표**(BTN1, MODE 4/7, BT1 ON 등) — 사용자 요청으로 이름표는 아래, 설명은 위로 옮김. 기기 선택 화면에서 고른 슬롯은 상자 테두리를 두 겹으로, 쓰는 중인 슬롯은 번호에 테두리를 두른다.
- 밝기·절전 (1.1.0): 어두운 곳 눈부심과 OLED 전력을 줄이려고 밝기(contrast)를 1로 두고, 화살표·아이콘·이름표·선택 표시는 채움/반전 없이 테두리로만 그린다. 값 위치 막대만 위치를 알아보도록 채운다. 아래 표의 \"머리줄\"은 이 이름표다.

**일반 화면**

| | 머리줄 | 가운데 | 아래 |
|---|---|---|---|
| OLED1 | BTN1 | ← (볼륨·PPT) / ↑ (휠·방향키) / 카메라 아이콘 | Prev page / Scroll up / Shutter |
| OLED2 | BTN2 | → / ↓ / 타이머 아이콘 (세는 중: 남은 초) | Next page / Scroll down / Timer 3s (세는 중: Cancel) |
| OLED3 | MODE n/7 | 앱 이름 (2줄) | Change / mode (2줄 — 한 줄이면 64px 폭에서 끝 글자가 잘림) |
| OLED4 | BT1 ON / BT1 wait (슬롯 번호) | 신호 종류(Wheel / Arrow / Volume / PgUp/Dn) + 설정 요약 (`Steps x3` 등 + Beep) | Settings |

**설정 화면**

| | 머리줄 | 가운데 | 아래 |
|---|---|---|---|
| OLED1 | SET n/m | 항목 이름 + 설명 2줄 + 큰 − | Less |
| OLED2 | VALUE | 값 + 위치 막대 + 큰 + | More |

두 값 항목(Beep, Cursor)은 −/+ 대신 OLED1에 `Off`/`Show`, OLED2에 `On`/`Hide` 선택 상자를 그리고 고른 쪽을 반전한다 (사용자 요청, 시험판에 반영됨). 1.1.0부터는 반전 대신 고른 쪽 테두리를 두 겹으로 그린다.
| OLED3 | BTN3 | X | Cancel |
| OLED4 | BTN4 | ▶ (다음) / ✓ (마지막) | Next item / Save |

**새로 필요한 화면**: 연결 기기 전환 대기 ("Pairing", 남은 시간), 시작 화면(이름·버전), 슬립 진입("Sleep"). 배치는 위 원칙을 따른다.

### 6.7 저장 (`ds::ConfigStore`)

모든 값은 **값 목록의 위치(U8)** 로 저장한다. 범위를 벗어난 값은 기본값을 쓴다 (ConfigStore 기본 동작). NVS 네임스페이스와 키 이름은 구현자가 정한다 (키 15자 이하). 웹 노출은 없으므로 `FIELD_NO_WEB`을 쓴다.

- 모드별: YouTube(Steps, Gap, Cursor), Kakao Webtoon(Keys, Gap), Series Webtoon(Steps, Gap, Cursor), Camera(Timer)
- 공통: Beep, 마지막 모드

## 7. 기타 결정

- BLE 이름: `DS Page Turner`, 외관값 HID Keyboard, PnP VID 0x303A(Espressif).
- 버전: 1.0.0. 프로젝트 폴더 `Page_Turner/`.
- 시험 펌웨어의 `spike_types.h` 등 이름은 정식 이름으로 정리한다. 구조체를 헤더로 둔 이유(Arduino 자동 함수 선언 순서)는 유지한다.
- 문서: `Page_Turner/README.md`(사용법·앱별 설정 방법, 특히 "웹소설은 앱에서 볼륨 키 넘김을 켜야 함"), `RELEASE_NOTES.md`, 루트 README 프로젝트 목록, 웹 플래셔 등록(메모리: 펌웨어 버전업 시 `firmware/` 배포본 갱신).

## 10. Camera 모드 BTN2 결정 과정

조사 결과 (2026-11-20):
- Android 키 코드에는 `KEYCODE_CAMERA`(셔터·카메라 실행)와 `KEYCODE_FOCUS`(초점)가 있다. 리눅스 HID 드라이버는 2023년 패치에서야 HID Camera Control 페이지(0x90)의 초점·셔터를 이 키로 연결했다. **폰 커널에 이 패치가 있는지에 따라 동작이 갈려 시험이 필요하다.**
- 삼성 카메라 앱은 설정 → 촬영 방법 → "볼륨 버튼 기능"에서 볼륨 키를 **사진 촬영/동영상 녹화**, **줌**, **시스템 볼륨** 중 하나로 고른다. 줌으로 두면 볼륨+/−가 확대/축소가 된다.
- 블루투스 키보드로 사진↔동영상 모드를 바꾸는 표준 키는 찾지 못했다.

시험할 후보 (BTN2):
1. Enter, Space (일부 카메라 앱이 셔터로 받음)
2. HID Camera Control 페이지 셔터(0x90/0x21)·초점(0x90/0x20)
3. 볼륨 키를 길게 누르고 있기 (삼성: 볼륨/셔터 길게 = 연속 촬영 또는 동영상 녹화 — 앱 설정에 따름)
4. 앱에서 볼륨 키를 "줌"으로 바꾼 뒤: BTN1 = 다른 셔터 키(1·2 중 동작하는 것), BTN2 = 줌

**결정 (2026-11-20)**: 사용자 기준은 **범용** — 삼성 등 특정 제조사 앱 설정에 기대는 후보(3·4)는 쓰지 않는다. 후보 2의 초점 키(0x90/0x20)를 실기 시험했으나 **반응이 없어** BTN2는 **딜레이 셔터**로 정했다.
