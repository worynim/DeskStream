**텍스트 생성부만 중국어로 교체**한 신규 프로젝트 첫 릴리즈입니다.

### ✨ 신규 기능

- **표준형 중국어 시간 표현** — `三点四十五分` 형식. 채택하지 않은 것: 구어체(`四点差一刻` — `差` 생략 시
  뜻이 뒤집힘), 시진(`申时` — 2시간 단위라 초 단위를 잃음).
  규칙 8개를 [`PLAN.md` §2.2](./PLAN.md)에 명문화했고 `test_chinese_time`가 전수 483건으로 고정한다.
  특히 자주 틀리는 세 곳 — **② 2는 `两`(이지 `二`가 아니다)** · **③ 10분 미만은 `零`을 넣는다**
  (`三点五分`은 3:5와 3:35로 오독된다) · **④ 30분은 `半`(31분은 다시 `三十一分`)** — 이 세 가지를
  회귀 테스트로 못 박았다.
- **기존 4화면 구조 유지** — 12H(`上午`·시·분·초) / 24H(`星期六` 요일만·시·분·초).
- **간체 ⇄ 번체 병용** — 차이는 `点`/`點`, `时`/`時`, `两`/`兩` **3글자뿐**이라 치환표 하나로 처리한다.
  전체 문자열을 2벌로 두지 않아 규칙이 어긋날 지점이 코드 전체에 단 하나다.
- **표시 방식 3단계 통합** — `简体 → 繁體 → 數字`를 **하나의 값**(`presentation`)으로 묶어 BTN2 short와
  웹 3번 항목이 같은 함수를 쓴다. 저장 필드는 NVS 마이그레이션이 필요 없도록 그대로 뒀다.
- **CJK 폴백 폰트 미도입** — Flash 여유 확보를 위한 의도적 결정(아래 "Flash"). 커스텀 폰트 업로드가 필수다.

### 🔧 구조적 결정 — 왜 새 모듈인가

`renderer.cpp`는 U8g2·LittleFS에 묶여 있어 네이티브 테스트가 불가능하다. AGENTS.md 테스트 규칙을 지키기 위해
값만 있고 I/O가 없는 부분을 분리했다.

| 모듈 | 책임 | 회귀 테스트 |
|:--|:--|:--|
| **`chinese_time_core`** (신규) | 표현 규칙 전체. **Arduino/String 미사용** — 호출자가 준 버퍼에 쓰고 실패 시 빈 문자열 | `test_chinese_time` 483건 |
| **`layout_engine`** (신규) | **1줄 전용** 배치 엔진. ENG판 2줄 엔진을 복사하지 않고 재설계 | `test_layout` 69건 (전수 758 표현) |
| `renderer_geometry` | 288B → `glyphW 32` / `drawW 48` / `xOffset −8` / `maxPerLine 4` 판별 | `test_geometry` 34건 |
| `chinese_time` | 위 순수 모듈의 `String` 래퍼 — API 형태를 ENG판에 맞춰 호출부 구조가 흔들리지 않게 | — |

**ENG판 `layout_engine`(260 LOC)를 복사하지 않은 이유**: 그것은 2줄 어절 줄바꿈·피치 사다리·잉크 계산을 위해
만들어진 것이고, 중국어판에서는 셋 다 불필요하다. 중국어 표현에는 공백이 없어 어절 = 전체 문자열이고,
CJK는 정사각형 그리드라 피치가 항상 32다. 복사하면 죽은 코드 200줄이 그대로 넘어온다 → **60~70 LOC로 줄였다.**

**표현 규칙의 "여유 0"** — 최장 표현이 정확히 4자라 4 × 32 = 128px = 화면 폭에 맞아떨어진다.
줄바꿈도 피치 사다리도 필요 없다. 대신 `test_layout`가 §3 전수 **758개 표현**을 순회해 최대 4셀인지 확인한다
(`layoutLine()`이 4셀 초과를 주면 `display_manager`는 **빈 화면**을 그리고 로그만 남긴다 — OLED를 보기 전까지
알아낼 방법이 없다). **여유가 0**이므로 표현 규칙이나 셀 수가 바뀌는 즉시 깨진다.

### 🔧 래스터 48×48 = 288 B — ENG판 v4/v5 실패를 처음부터 배제

ENG판은 2줄 × 64px 래스터 × 150% 줌에서 **좌우 클리핑(v4)**, 상하 클리핑(v5)을 각각 실패했다.
중국어판은 ENG판과 정반대다 — 2줄이 없고 라스터가 화면 밖으로 나가지 않는다.
**래스터가 피치와 같은 크기**(폭 48 = 피치 32 + 좌우 여유 8, 높이 48 = 피치 32 + 위아래 8)이면 경계 클리핑이
원리상 생기지 않는다. 글자당 6 × 48 = 288 B. 슬라이더는 20~40px로 제한했고 기본값 32px는 겹침이 0이다
(40px를 32px 피치에 놓으면 인접 글자와 4px씩 겹쳐 CJK 판독이 불가능).

### 🔧 문자집합 — 간체·번체 **둘 다 34자**

원안은 "간체 34 + 번체 전용 3 = 37자"였으나 **틀렸다.** 34자에 이미 `点` `时` `两`가 들어 있고 번체는 이 3자를
**치환**할 뿐 추가하지 않는다 → 번체도 34자다. 중복 0개를 실측으로 확인했다.
슬롯당 34 × 288 B = **9,792 B** (ENG판 14,592 B 대비 **33% 감소**).

### 🔧 숫자 모드의 단위 중복 버그 (계획 정정 5건 중 3번)

`.ino`가 숫자에 `" 时"`를 덧붙이도록 계획했으나, `chinese_time.cpp`의 `withUnit()`가 **이미** `"13 时"`를
돌려준다. 그대로 쓰면 `"13 时 时"` = 6셀 → 4셀 한계를 넘어 **그 화면이 통째로 빈칸**이 된다.
ENG판은 `getNumericHour()`가 숫자만 돌려줘서 `.ino`가 단위를 붙이던 구조와 다르므로 같은 코드를 옮기면 안 된다.

#### 결함 6 — "Empty Slot"을 세 번 고친 기록

같은 증상에 원인이 **셋** 있었다. **①②③④를 함께 고쳐야 화면이 바뀐다** — 다른 프로젝트를 고칠 때도
④까지 포함해야 한다(PLAN §📌에 정확한 파일·줄을 적어 뒀다).

| | 원인 | 조치 |
|:--:|:--|:--|
| ① | 업로드마다 `?slot=${els.slot.value}`를 읽음 — 중간에 슬롯을 바꾸면 도착점이 달라짐 | 시작할 때 `targetSlot`을 **한 번만 읽어 고정** |
| ② | 이름이 **별도 POST + 조건부**(`if (els.fIn.files[0])`)로 갔음 — 요청이 빠지면 슬롯에 **글리프만 남는다** | `POST /upload?slot=N&font=<이름>` — **같은 요청**에 실림. 미선택이면 업로드를 시작하지 않고 중단 |
| ③ | 이름표를 **현재 슬롯**에 썼음 — 글리프는 `/f2`로, 이름표는 `/f0`으로 감 | `setSlotName(slot, name)` 신설. `setFontName()`은 여기에 위임 |
| ④ | 이름 길이 **32바이트 상한**이 실제 폰트 이름(`MFXuanRen_Noncommercial-Regular.ttf` = 35 B)을 **조용히 거부** | 상한의 근거 주석("파일명으로도 쓰인다")이 **사실이 아니라** 상수가 거짓 전제에서 나왔음이 확인됨. 경로는 `"/f" + slot + "/name.txt"` 리터럴이고 이름은 **내용**으로만 들어간다. → `FONT_NAME_MAX_LEN 64` |

> 🔴 **교훈: "값이 없을 때"도 로그를 남겨야 합니다.** 두 번의 진단이 어려웠던 이유는 코드가 틀려서가 아니라
> **실패가 침묵했기 때문**입니다. 거부 시 `[WEB] Slot name rejected: … (len=35; 1..64 bytes, …)` 로 남기고,
> 업로드 시작 시 `fontArg=%d`를 **무조건** 찍습니다. **이 줄은 지우지 말 것.**

### 🧹 구조 개선

- **`handleSetConfig()`가 79줄**로 AGENTS.md의 50 LOC 한계를 넘어 **JSON 값의 종류**를 경계로 분할
  (`applyIntSettings` / `applyBoolSettings` / `applyPresentation` / `applyTimezone` / `applyFontName`).
  정수·불리언은 범위 검사만, 문자열은 따옴표 위치 파싱과 별도 검증기가 필요하다. 섞어 두면
  "값이 안 바뀌었는데 이유를 알 수 없다"가 된다.
- **`presentation()` 통합으로 진입점 제거** — `setScriptType()`과 `setDisplayMode()`을 **삭제**했다.
  둘 다 남아 있으면 같은 상태를 만드는 길이 두 벌이 되어 어느 쪽이 규칙인지 알 수 없다.
- **숫자 모드는 검증을 건너뜀** — 한자 모드 진입은 글자 검증이 필요하지만(없으면 조용히 빈칸),
  `數字`는 라틴 폴백 폰트만으로 그려진다. 예전 `"Font Required!"` 가드를 두면 **폰트를 한 번도
  올리지 않은 기기에서 BTN2 버튼이 dead**가 된다(한자 칸 2개가 영구히 막힘).
- **본문 없는 POST에 400 응답** — ENG판에서 승계된 결함. `fetch()`가 "응답 없음"으로 보고
  저장 실패처럼 보였다.
- **`fontArg` 순서 계약** — `/api/config` POST에서 `applyIntSettings`가 `applyFontName`보다 **먼저**
  돌아야 슬롯이 먼저 반영되고 이름표도 같은 슬롯에 쓰인다. 이 순서가 계약이며 회귀 테스트가 검증한다.
- **빈 슬롯 표기 통일** — 부팅 캐시 `"Empty"` / `setFontSlot()` `"Empty Slot"`로 갈라져 있던 것을
  `"Empty Slot"`으로 통일.
- **`setFontSlot()`이 `_slotNames[]`를 갱신** — 그때까지 `/api/config`의 `slotNames`가 **부팅 시점 값으로
  멈춰** 슬롯을 옮겨도 드롭다운이 사실과 어긋났다.
- **CJK 폴백 폰트 미도입** — Flash 여유 확보. 대신 커스텀 폰트를 필수화했다.

### ⚠️ 이 릴리즈가 아직 하지 않은 것

정직하게 남깁니다. **기계적으로 검증된 것과 실기로 검증해야 하는 것을 구분**했습니다.

**✅ 기계적으로 검증됨** — 네이티브 테스트 665 단언 + JS 교차검증 696행 + `web_fixes_test` 92건,

**❌ 실기 확인 필요** (PLAN §7의 검증 게이트 · Step 12)

1. **검증 게이트** — 32px 한자 가독성, 4자 폭 정합성, `三点零五分` 정확성, `三点半` 규칙, 세로 중앙 정렬.
   게이트를 통과하지 못하면 피치 28px가 대체안이다(ENG판과 달리 `SEVENTEEN`(9자) 제약이 없어
   **피치 축소가 유일한 대안**이다).
2. **애니메이션 5종 수동 검증** (Step 12) — 미완.
3. **백지 화면 수정 재확인** — `send_P`로 고쳤으나 무관한 원인으로도 백지는 발생할 수 있다.
   여전히 백지면 그때는 시리얼 로그를 함께 본다.
4. **슬롯 0·2 재업로드** — 결함 6의 ①②③④를 함께 고쳤으니, 각 슬롯을 한 번씩 다시 업로드해
   `[WEB] Slot N name = …` 가 찍히고 드롭다운이 바뀌는지 본다. **NVS 삭제는 필요 없다.**
   여전히 거부되면 `len=` 값이 결정적이다.
5. **실제 다국어 렌더링** — 간체 폰트와 번체 폰트를 번갈아 업로드해 3글자 차이
   (`点`/`點`, `时`/`時`, `两`/`兩`)가 정확히 반영되는지 눈으로 확인.
6. **`FALLBACK_BASELINE 42`는 계산값이지 실측이 아니다** — 실기에서 눈으로 확인해야 한다.
