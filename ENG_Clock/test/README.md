# ENG_Clock Tests

A collection of unit tests and cross-validation that run on the host (g++ / node). They verify the logic without uploading firmware.

## How to Run

```bash
# All JS ↔ firmware cross-validation (recommended — runs everything at once)
bash test/js/run_all.sh

# Native C++ unit tests (individually)
cd test
L=../../libraries/DeskStreamCore/src   # layout_engine.cpp uses util/ds_utf8.h
g++ -std=c++11 -I.. -I$L test_english_time.cpp ../english_time_core.cpp -o /tmp/test_english_time && /tmp/test_english_time
g++ -std=c++11 -I.. -I$L test_layout.cpp ../layout_engine.cpp ../renderer_geometry.cpp ../english_time_core.cpp -o /tmp/test_layout && /tmp/test_layout
g++ -std=c++11 -I.. -I$L test_geometry.cpp ../renderer_geometry.cpp -o /tmp/test_geometry && /tmp/test_geometry
```

> Since v1.1.0, the TZ validation, I2C retry, UTF-8 and NTP policy tests have moved to the shared library:
> `bash libraries/DeskStreamCore/test/run_all.sh` (from the repository root).

## js/ — Cross-Validation Scripts

`run_all.sh` runs in this order: (1) build the firmware dumper → (2) extract the shipped JS from `web_pages.h` → (3) run the comparisons.
It checks **numerically** that the web preview JS and the firmware renderer produce the same results (defense against risk #2).

| Script | What it checks |
|:--|:--|
| `layout_crosscheck.mjs` | Compares `layoutWrap` two-line word splitting |
| `time_crosscheck.mjs` | Compares English time expressions |
| `packGlyph_test.mjs` | Rasterizer (TTF → bitmap) |
| `preview_cache_test.mjs` | Preview cache (bug regression) |
| `web_fixes_test.mjs` | Web fix regressions (bugs 1·2·3) + items propagated from the Chinese edition §📌 A-1·A-2·A-3·A-4·A-5·B-1 |
| `firmware_wiring_test.mjs` | Firmware wiring regressions (fixes 1·2·3) |
| `extract_from_web_page.mjs` | Extracts `web_pages.h` → `_extracted.mjs` (verifies the shipped code as-is) |
| `make_baseline_check.mjs` | Manual vertical centering check page → `/tmp/eng_bias_check.html` |
| `make_browser_check.mjs` | Real browser pixel check page → `/tmp/eng_browser_check.html` |
| `make_overlap_check.mjs` | Glyph overlap regression check page (v5, PLAN §6.14) → `/tmp/eng_overlap_check.html` |
| `make_spacing_check.mjs` | Spacing expansion (§6.16) check page for 6 representative strings → `/tmp/eng_spacing_check.html` |
| `make_spacing_diag.mjs` | Classifies failures of the check above as "geometrically impossible" vs "real defect" → `/tmp/eng_spacing_diag.html` |
| `make_spacing_sweep.mjs` | §6.16 — exhaustive sweep of **every string** the clock actually shows × font size → `/tmp/eng_spacing_sweep.html` |

Open the HTML generated by `make_*.mjs` in a browser to check it (can be automated with puppeteer etc.).

**Why this is not automated**: `make_spacing_check.mjs` explains why it looks at only 6 representative strings —
the ink width of `measureText()`/`fillText()` is determined only by **real canvas pixels**, and a synthetic Node test
cannot replace the browser's anti-aliasing threshold. So this family is not in `run_all.sh` and is left as a
manual check. It is a deliberate judgment that **numbers alone cannot capture the threshold**, so do not move it back into automation.

`_extracted.mjs` is generated, so it is not committed (see `js/.gitignore`).

## Rules

- Do not commit compiled binaries (keep build outputs in `/tmp` or delete them after running).
- When firmware code changes, update the matching cross-validation expectations too.
- New code gets new tests (AGENTS.md test rules).
